# 漫画阅读性能验证结果

## 测试环境

- 对照对象：旧正式容器 `http://127.0.0.1:13000` 与本次生产等价镜像 `http://127.0.0.1:13001`。
- 数据与图片：两者使用同一远端 MySQL 与图片 CDN；每轮清空并禁用浏览器 HTTP cache。
- 浏览器：Chrome headless/CDP，390x844、device scale factor 3、4 倍 CPU throttle、150ms RTT、1.6Mbps 下行、750kbps 上行。
- 核心样本：漫画 585，第 1 话，共 280 页；P1 与 localStorage 恢复 P201 各 5 次冷启动。
- 可读时间：目标 `img` 的网络完成、`decode()` 完成后再经过两个 `requestAnimationFrame`，不是 Loading 消失时间。
- 临时复现脚本：`/tmp/measure-reader.mjs` 与 `/tmp/measure-reader-scroll.mjs`，未纳入产品代码。

## Web 恢复 P201，5 次冷启动

旧实现仅 1/5 在 30 秒内完成，且完成时已漂移到 P274；该次 P201 的请求开始为 2948.2ms、下载完成 19633.7ms、可读 19666.7ms，可读前请求 35 张漫画图。其余 4 次 30 秒超时。

新实现 5/5 成功，均准确保持 `P201/P280`、本地进度 200、`scrollY=110931`：

| 指标 | 新实现中位数 |
| --- | ---: |
| 目标图请求开始 | 2016.4ms |
| 目标图下载完成 | 2802.8ms |
| 目标图实际可读 | 2853.2ms |
| 可读前漫画图片请求 | 2（SSR P1 + 恢复目标 P201） |
| 目标图优先级 | High |
| 已挂载图片 | 5 |
| DOM Nodes | 766-767 |
| Layout 次数 | 17-24 |

以旧实现唯一成功但错误落页的结果对比，新实现目标图可读缩短约 16.814 秒 / 85.5%，完成率由 1/5 提升到 5/5。SSR 无法读取 localStorage，因此仍会先请求 P1；完全消除此请求需要服务端可读进度协议。

部分新实现采样的 LCP 是 P201，另一些仍是 SSR P1，证明 LCP 不能稳定代表恢复目标图，因此未作为主指标。

## 连续滚动 P1 到 P6

测试在每张目标图可读后立即跳到下一页，是比正常阅读更激进的带宽竞争条件：

| 页面 | 新实现到达视口后的等待 |
| --- | ---: |
| P1 | 1930.6ms（从导航开始的可读时间） |
| P2 | 2295.6ms |
| P3 | 110.3ms |
| P4 | 29.0ms |
| P5 | 2035.6ms |
| P6 | 20.0ms |

新实现无图片失败、超时或重复 URL，最终准确为 P6、本地进度 5；共请求并挂载 9 张漫画图。旧实现单次样本虽然提前并发后续图片，但在视口 P2 时页码已显示 P5，最终视口 P6 却错误保存 P10。新实现选择先保证当前图，再用 600px 下方窗口预取约两页，极端无阅读停留的 P2/P5 仍可能等待。

## 章节 API 与服务端

- 同一 280 页章节的旧/新 JSON 逐字段相等，均为 24,654 bytes，页序从 index 0 到 279。
- 结构性 SELECT 从约 9 次（含设置读取）降到约 4 次。
- 同库第一组 5 次 API TTFB：旧中位数 129.587ms，新中位数 72.245ms，减少 57.342ms / 44.2%。最终暖库复测为 98.369ms 对 83.327ms，减少 15.042ms / 15.3%；不同缓存热度下方向一致。
- 阅读页 HTML 总完成时间中位数从约 138.4ms 降到 77.4ms。旧实现会先流出等待关键数据的空 shell，所以其较早 TTFB 与图片可读无直接对应关系。
- 独立终审发现初版 selector 用 JavaScript 严格大小写比较模拟 MySQL slug collation，会让大写 slug 从 200 回归为 404。最终实现改由 SQL 投影 collation 命中标记。真实生产库复测中，大写作品详情、章节 API 与 reader 旧/新均为 200；详情 597B、章节 8557B 的 JSON 均逐字节一致。

## 长章节与布局

- 674 页样本：新实现首图 2054.5ms 可读，只发起 1 个可读前图片请求，目标优先级 High；1443 个 DOM elements、1545 Nodes、约 5.26MB JS heap、8 次 Layout。
- 292 页正方形图片样本：新实现首图 1930.5ms 可读并保持 P1；浏览器识别实际 1024x1024。
- 当前数据表/API/生产者只有 URL 与页序，没有 width/height。新实现移除了会为长章节累积错误高度的绝对 intrinsic size，保留响应式 900:1280 未加载占位，加载后使用真实 intrinsic size。
- 现有 trace 没有证明长章节存在 DOM 或内存瓶颈，因此没有引入虚拟列表，避免上下滚动白屏及恢复偏移。

## Android 静态验证

- reader 内容门禁由“章节 + 完整漫画 + 收藏”降为只等待章节响应。
- 当前图在 Telephoto `isImageDisplayed` 且经过两帧后才开放后两页预取。
- 40 页顺序阅读的显式调度从 150 次降到最多 39 个唯一 URL；首图阶段由当前页加后 4 页竞争降为仅当前页。
- 恢复页直接初始化 `LazyListState`；相同章节的新 reader entry 不重复请求，切章/退出会取消 Coil Disposable。
- Android 打包/发布根契约测试 7/7 通过；根目录全量 Node 测试 241/241 通过，Kotlin 关键路径已做静态复核，未运行本地 Gradle。
