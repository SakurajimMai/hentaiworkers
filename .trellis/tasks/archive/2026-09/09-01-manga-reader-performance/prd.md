# 优化漫画阅读首图与连续滚动性能

## Goal

缩短 Web 与 Android APK 从进入章节到当前阅读页第一张漫画图真正可见、可读的时间，并保证连续滚动时附近图片及时出现；同时减少重复请求、无效下载、服务端负载和前端无效渲染，保持页序、权限、收藏、阅读进度、错误恢复和现有阅读功能正确。

“图片可读”统一定义为目标漫画图已完成网络传输与解码，并至少经过两个渲染帧；不能用接口返回、骨架出现、Loading 消失或组件 `onSuccess` 代替。

## Requirements

### Critical path

- Web 阅读页必须在漫画开关、发布状态和当前章节图片清单校验完成后尽快输出阅读器，不得继续等待站点页头、页脚、收藏、广告或浏览统计。
- Android 阅读器必须以章节响应作为图片展示的关键依赖；完整漫画详情与收藏状态只能作为可合并的非关键结果，其失败或超时不得阻止章节图片显示。
- Web 与章节 API 必须共用一次解析漫画、一次读取章节列表/当前章节和一次读取页列表的专用查询路径，避免重复加载漫画及无用的完整数据。
- 浏览统计必须脱离首图响应关键路径，同时保持原有去重和身份语义。

### Image loading and scrolling

- Web 初始只给当前必需图片最高优先级；附近图片只能在当前页之后以受控窗口加载，不得让多张远端图片抢占首图带宽。
- Web 的真实可见页识别与预加载观察必须分离；预加载范围绝不能改变当前页、页码显示或持久化进度。
- Android 必须等当前页由 Telephoto 确认真正显示后，才预取有限的后续图片；同一章节的同一 URL 最多显式调度一次，离开章节时取消尚未完成的预取。
- 恢复阅读位置时，Web 和 Android 都应优先请求恢复页，避免先下载第一页后再跳转。若 Web 因客户端本地存储只能在水合后得知恢复页，必须如实记录该平台限制。
- 单页图片失败必须只影响该页，并保留重试；其他页面和阅读器交互继续工作。
- 保留准确页序、页码跳转、连续滚动、阅读进度恢复、收藏、章节切换、广告位、全屏和安全区行为。

### Rendering and layout

- 避免页码、工具栏或滚动状态变化触发整章图片列表的无意义重建；页面节点和回调应保持稳定。
- 保持异步图片解码，不引入同步解码或整章图片加载门禁。
- 继续使用 Web 的按需图片挂载和 Android 的 `LazyColumn` + Telephoto/Coil；本次没有内存 trace 证明需要新的虚拟列表，因此不得为了优化而重写阅读器。
- 图片占位必须使用当前可获得的最佳宽高比。数据库与发布协议目前没有真实尺寸，不能把固定猜测宣称为准确解决；生产者尺寸契约与旧数据回填作为明确的后续问题记录。

### Compatibility and scope

- 不改变公开章节 API 的响应结构、发布/下架校验、图片 URL 顺序或 Android 的 `/cdn-img` 重写规则。
- 不新增长期章节缓存，除非同时有可靠的发布/下架失效链路；本任务不以缓存陈旧风险换取表面速度。
- 不重写项目，不迁移图片存储，不移除外部图床或 Cloudflare，不恢复已移除的历史产品范围。
- 不在本地运行 Gradle；Android 构建和设备级验证由远端 GitHub Actions/真机承担。

## Acceptance Criteria

- [ ] Web 阅读路由不再执行 `(site)` 页头/页脚的身份与设置查询，收藏、广告和浏览统计均不阻塞核心阅读器 HTML。
- [ ] 专用 reader-data 查询保持 slug 优先、数字 ID fallback、漫画/章节发布过滤和 `page_index` 顺序；正常数字 ID 章节 API 的结构性读取由约 9 次降至约 4 次或更少。
- [ ] `generateMetadata` 与阅读页在同一请求内复用 reader-data，不重复执行相同数据库查询。
- [ ] Web 首个关键图片带有高获取优先级；初始不再同时将 P1/P2 都作为关键 eager 图片，预加载观察器不会写当前页或进度。
- [ ] 390x844、292 页章节、`scrollY=0` 且不滚动的自动化用例始终保持 P1/P292，不能再错误保存 P6。
- [ ] 匿名 Web 阅读不发送 `/api/me/manga-progress`；登录用户只在实际可见页变化后防抖同步，离开时保留最终页。
- [ ] Web 单页组件/列表具有稳定引用或 memo 边界；工具栏/页码状态变化不会重新计算全部图片节点。
- [ ] Android 收到章节成功结果后即可发布阅读内容，不等待完整漫画或收藏请求；可复用详情页/上一章节已有数据，并防止过期异步结果污染新章节。
- [ ] Android `LazyListState` 从恢复页初始化；当前图未由 Telephoto 确认可见前不显式预取后续图片。
- [ ] Android 同一章节每个后续 URL 最多显式预取一次，离开章节时释放预取任务；40 页顺序阅读的调度上限由现有 150 次降至最多 39 次，首图阶段从当前页加后 4 页竞争降为仅当前页。
- [ ] Web 与 Android 均保留单图失败隔离、重试、正确页序、章节导航、收藏、进度恢复和清晰原图。
- [ ] 自动测试覆盖查询契约、可见页与预加载分离、恢复页边界、匿名进度、预取去重/取消和失败隔离的可测试部分。
- [ ] `npm run typecheck`、相关测试、`npm run check:boundaries`、`npm run build` 通过；`npm run lint` 若仍失败，必须区分既有失败与本次回归。
- [ ] 在与基线相同的生产或等价环境中，以冷缓存、390x844@3x、4x CPU、150ms RTT、1.6Mbps 下行至少重复 5 次，报告当前页图片请求开始、下载完成、`decode()+2 RAF` 可读时间、首屏图片请求数、恢复页请求顺序和 LCP 元素。
- [ ] Android 真机/APK 报告章节响应、当前图请求开始、Telephoto `isImageDisplayed`、连续滚动等待、失败率和内存；若当前回合无法执行，明确列为未完成验证，不用 Loading 时间替代。

## Baseline

- Web 生产基线，章节 585/P1/280 页：请求开始 332ms，下载完成 2801ms，实际可读 2873ms；LCP 2824ms，元素确认是 `img.reader-image`。
- Web 恢复 P201：目标图片 1101ms 才开始、3293ms 可读；P1/P2 已在 281/282ms 抢先请求，恢复页请求晚约 820ms。
- Web 章节 584/292 页不滚动：`scrollY=0`，本地进度错误变成索引 5，界面显示 P6/P292。
- Android 现有 40 页顺序阅读显式预取调度为 150 次、39 个唯一后续 URL；首图阶段同时竞争当前页和后 4 页。
- 正式章节 API：20 页样本 TTFB 115-248ms；674 页样本 130-152ms，JSON 54,768B，gzip 约 7.2KB。
- Android 图片代理样本：冷请求 TTFB 0.959s/完整 1.800s，暖请求 0.030s/完整 0.045s。此 HTTP 数据不代表手机图片已解码可读。

## Non-goals

- 不用骨架屏、隐藏 Loading 或动画调整伪装性能提升。
- 不用虚拟列表、整章分页协议、存储迁移或图片质量下降作为本次默认方案。
- 不声称解决生产图床背后对象存储、真实手机网络、数据库地理距离或旧图片尺寸，因为仓库中缺少相应证据与控制面。
