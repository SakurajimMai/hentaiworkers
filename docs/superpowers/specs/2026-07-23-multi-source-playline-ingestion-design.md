# 多资源站主资料与补充线路采集设计

## 背景

当前每个 MacCMS 采集模板都会把标题、简介、封面、标签、剧照和播放线路作为一个完整条目提交。控制面按 `source + source_id` 查找 `anime_work_sources`，因此同一部动漫来自 iKun 和红牛时会生成两条 `anime_works`，或者后一次采集覆盖前一次保存的完整线路 JSON。

目标是允许管理员把一个模板设为主资料源，其他模板设为补充线路源。例如：

- iKun 模板采集并更新详情、封面、标签和 iKun 播放线路。
- 红牛模板只把红牛播放线路追加到同一部作品。
- 前台最终显示多个播放线路，但作品资料始终以 iKun 为准。

## 目标

1. MacCMS 模板可以选择完整采集或仅补充播放线路。
2. 完整采集继续创建和更新作品资料，同时保留其他资源站已经写入的线路。
3. 补充线路采集只能更新播放线路和来源映射，不得更新作品资料或标签。
4. 不同资源站首次关联时按规范化标题和年份唯一匹配。
5. 未匹配或匹配不唯一时安全跳过，不创建重复作品。
6. 旧模板保持完整采集行为，不需要数据库迁移。

## 非目标

- 不把多个资源站组合到同一个模板或同一个采集任务。
- 不自动决定哪个资源站的资料质量更高。
- 不实现人工作品映射界面。
- 不允许补充线路源在找不到主作品时创建占位作品。
- 不改变 Hanime 的下载、上传和里番片库流程。

## 模板配置

在 `CrawlerProfileConfig` 根级增加可选字段：

```ts
ingestionMode?: 'full' | 'playback_only';
```

兼容规则：

- 字段缺失时按 `full` 处理，保证旧模板和旧任务快照行为不变。
- MacCMS 模板表单显示“采集详情资料（主资料源）”复选框。
- 复选框勾选时保存 `full`，未勾选时保存 `playback_only`。
- Hanime 不显示该选项，并始终使用 `full`。
- 编辑旧模板时复选框默认勾选。

模板列表和任务详情显示 `full` 或 `playback_only`，便于管理员确认任务用途。

## 任务与信任边界

模板启动后，`ingestionMode` 随配置写入不可变的 `config_snapshot_json`。Worker 根据快照减少无用的封面下载，但控制面不能信任 Worker 自报模式。

提交条目时，`CrawlerResultService` 在已经验证租约的事务内读取当前 Job 的 `config_snapshot_json`，解析出真实模式，再传给目录入库端口。因此：

- Worker 不能把补充线路任务伪装成完整采集。
- 重试任务继续使用创建时的模板版本和模式。
- 后续编辑模板不会改变已经入队的任务。

若历史 Job 快照缺少该字段，则控制面按 `full` 处理。

## Worker 行为

### 完整采集

`full` 保持现有 MacCMS 解析能力：提交标题、各语言标题、简介、封面、标签、年份、日期、演职员、别名、地区、语言、更新时间、默认视频地址和全部解析出的播放线路。

启用本地封面下载时，Worker 继续下载封面并提交本站封面路径。

### 补充线路

`playback_only` 仍需要从上游读取以下最小信息：

- `source` 和 `source_id`，用于建立稳定来源映射。
- 标题及可用的英文名、日文名、别名，用于首次匹配。
- 年份，用于消除同名作品歧义。
- 默认视频地址和 `play_lines`，用于线路合并。

Worker 不下载本地封面，不查询或下载剧照。即使上游响应包含简介、封面和标签，控制面也不会把这些字段写入作品资料。

## 作品匹配

补充线路条目按以下顺序解析目标作品：

1. 使用 `source + source_id` 查询 `anime_work_sources`。命中后直接锁定对应作品。
2. 未命中时，从条目的标题、英文名、日文名和别名生成规范化标题集合。
3. 查询候选 `anime_works`：有上游年份时使用现有 `release_year` 索引读取同年和年份为空的候选；没有上游年份时读取可用作品候选。对候选的同类标题字段使用相同规范化函数。
4. 上游与作品双方都有年份时必须相等；任一方没有年份时不以年份排除候选。
5. 只有一个作品命中时建立新的 `anime_work_sources` 映射。
6. 没有作品命中时，以 `CATALOG_MATCH_NOT_FOUND` 将 Job Item 标记为 `skipped`。
7. 多个作品命中时，以 `CATALOG_MATCH_AMBIGUOUS` 将 Job Item 标记为 `skipped`。

标题规范化规则：

1. Unicode `NFKC` 规范化。
2. 转为小写并去除首尾空白。
3. 去除所有 Unicode 空白和标点符号。
4. 别名先按中英文逗号、顿号、斜线、竖线和分号拆分，再分别规范化。
5. 丢弃空字符串并去重。

匹配失败不会创建 `anime_works`，也不会建立来源映射。管理员可以先运行主资料源，再重试补充线路任务。

## 线路合并

目录入库端口把现有 `play_lines_json` 解析为线路数组，再与本次来源线路合并：

- 线路主键优先使用非空 `flag`，否则使用 `name`。
- 主键比较进行 `NFKC`、去除首尾空白和小写转换。
- 本次存在同主键线路时，用新线路完整替换旧线路，包括剧集名称和 URL。
- 本次新增线路追加到现有线路末尾。
- 其他主键线路保持原顺序和内容不变。
- 本次没有有效线路时不修改 `play_lines_json`。
- 完整采集使用当前主资料源的首个有效线路更新 `stream_url` 和 `stream_format`，作为兼容默认播放地址。
- 补充线路采集不修改 `stream_url` 和 `stream_format`，因此默认播放地址继续来自主资料源；前台多线路以 `play_lines_json` 为准。

完整采集和补充线路采集都使用同一线路合并函数。因此 iKun 再次完整采集时只更新 iKun 线路，不会删除红牛线路；红牛再次采集时也只更新红牛线路。

## 入库事务

### 完整采集路径

1. 按来源映射查找作品。
2. 不存在时创建 `anime_works` 和主来源映射。
3. 更新完整作品资料。
4. 合并当前来源线路。
5. 替换主资料源提交的标签。

### 补充线路路径

1. 按来源映射查找作品。
2. 首次出现时执行标题和年份唯一匹配。
3. 唯一命中后建立来源映射。
4. 仅更新 `play_lines_json` 和 `updated_at`。
5. 不调用作品资料更新和标签替换函数。

匹配、来源映射和线路更新必须在现有 Crawler Unit of Work 事务内完成。并发创建同一来源映射时复用当前唯一键冲突处理；失败事务不得留下孤立作品或半完成映射。

## API 与结果模型

Worker 条目提交协议不新增可伪造的模式字段。服务端从 Job 快照取得模式。

目录入库结果扩展为可辨识联合：

```ts
type CatalogIngestionOutcome =
  | {
      kind: 'upserted';
      animeId: number;
      created: boolean;
      target: 'legacy_animes' | 'anime_works';
      workId?: number;
    }
  | {
      kind: 'skipped';
      code: 'CATALOG_MATCH_NOT_FOUND' | 'CATALOG_MATCH_AMBIGUOUS';
      message: string;
    };
```

现有 Hanime `legacy_animes` 结果仍返回 `upserted`。当结果为 `skipped` 时，`CrawlerResultService` 写入 `crawler_job_items.status = skipped`、对应错误码和安全错误说明，并且不写 `anime_id`。

## 管理后台

MacCMS 模板表单在封面选项附近增加一个复选框：

```text
[x] 采集详情资料（主资料源）
```

辅助说明：

```text
勾选：更新详情、封面、标签和当前线路。
未勾选：只向已有作品补充当前播放线路；未唯一匹配时跳过。
```

该控件遵循现有表单样式，不增加单独设置页面。模板列表显示“主资料”或“仅线路”，任务列表继续显示来源，同时显示模式。

## 错误处理与可观测性

- 未匹配和多匹配属于预期数据结果，计入 `skipped`，不让整个任务失败。
- 线路 JSON 损坏时按空线路处理，避免阻塞本次有效线路更新。
- 补充源返回空线路时条目标记 `skipped`，错误码为 `RESULT_INVALID`，不得只建立空来源映射。
- 数据库异常继续沿用 `DATABASE_TRANSIENT` 或现有内部错误处理。
- Job 详情展示 Item 的匹配错误码和说明，帮助管理员修正运行顺序或来源标题。

## 测试策略

### 配置和界面

- 新建 MacCMS 模板能保存两种模式。
- 编辑旧模板默认显示主资料模式。
- Hanime 始终为完整采集。
- 模板与任务列表显示模式。

### Worker

- 补充线路模式不调用本地封面保存。
- 补充线路模式仍提交标题、年份、默认视频地址和线路。
- 完整模式保持当前封面与完整资料提交行为。

### 应用服务

- 模式取自 Job 快照，而不是 Worker 请求。
- 历史快照缺少模式时使用 `full`。
- 匹配失败结果写为 skipped Job Item。

### MariaDB 入库

- 主资料源创建作品并写入资料、标签和线路。
- 补充源唯一匹配后绑定到同一 work_id，只追加线路。
- 补充源不覆盖标题、简介、封面、标签和年份。
- 无匹配与多匹配不创建作品或映射。
- 重复补充采集更新同线路但保留其他线路。
- 主资料源再次采集保留补充线路。
- 并发来源映射保持幂等且不产生孤立作品。

## 部署与兼容

本功能不新增数据库表或字段，不需要迁移。部署仍只需：

```bash
docker compose up -d
```

旧模板和已经排队的旧快照默认采用完整采集。启用补充线路模式前，应先运行主资料源模板，使目标作品已经存在。

本功能不会自动合并启用前已经由多个资源站创建的重复作品。若补充来源已经绑定到旧的重复作品，需要先在后台清理重复记录，再重新运行补充线路模板。
