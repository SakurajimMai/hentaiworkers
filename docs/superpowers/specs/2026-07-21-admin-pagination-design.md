# 后台数字分页设计

## 目标

将后台通用 `AdminPagination` 从仅显示“上一页/下一页”改为紧凑的数字分页导航，形式为 `< 1 2 3 4 … n >`。所有现有后台调用页面自动获得相同行为，前台已有数字分页保持不变。

## 范围

- 修改 `components/admin/admin-pagination.tsx`。
- 增加可独立测试的页码序列生成逻辑。
- 覆盖当前使用 `AdminPagination` 的用户列表和标签列表。
- 不修改列表查询、每页数量、数据库访问或前台 `components/pagination.tsx`。

## 交互与显示

- 总页数不超过 7 页时显示全部页码。
- 总页数较多时始终显示第一页、最后一页和当前页附近页码。
- 当前页靠近开头时显示 `1 2 3 4 5 … n`。
- 当前页位于中间时显示 `1 … p-1 p p+1 … n`。
- 当前页靠近结尾时显示 `1 … n-4 n-3 n-2 n-1 n`。
- 左右按钮使用现有箭头图标；第一页禁用向左按钮，最后一页禁用向右按钮。
- 当前页具有明确的选中样式和 `aria-current="page"`，禁用按钮具有 `aria-disabled="true"`。
- 保留“第 p/n 页 · 共 x 条”的摘要，并允许导航在窄屏下换行，不产生横向溢出。

## URL 行为

- 页码链接继续使用服务端 `Link`，不引入客户端状态。
- 点击页码只替换 `page` 参数。
- 调用方传入的搜索和筛选参数完整保留。
- 空值查询参数不写入 URL。

## 边界处理

- 计算页码前将 `totalPages` 规范为至少 1。
- 将用于导航的当前页限制在 `1..totalPages`，避免产生第 0 页或超过末页的链接。
- 省略号仅作为不可点击文本，不生成重复 key 或链接。

## 测试

- 小页数输出完整连续页码。
- 首部、中部、尾部窗口输出正确页码和省略号。
- 越界当前页能够被规范化。
- 生成链接时保留查询参数并正确替换页码。
- 组件包含数字导航、当前页语义和首尾禁用状态。

## 验收标准

1. 后台分页显示数字页码和左右箭头，不再只显示“上一页/下一页”。
2. 页数较多时省略号位置正确，第一页和最后一页始终可见。
3. 点击页码后搜索及筛选条件不丢失。
4. 用户列表和标签列表无需单独修改即可使用新分页。
5. 目标测试、完整 TypeScript 测试、ESLint 和类型检查通过。
