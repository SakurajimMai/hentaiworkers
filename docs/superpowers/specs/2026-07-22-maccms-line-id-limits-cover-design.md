# MacCMS 线路标识、采集上限与封面开关设计

## 目标

修正 MacCMS 采集模板的三个控制项，使其语义可预测且与播放器入库数据一致：

1. 将“从资源站选择线路”和“站内播放线路标识”拆分。
2. 支持最大条目设为 `0`，表示采集已配置页数中的全部条目。
3. 使“下载并保存封面”复选框真正控制封面写入与外部存储上传。

## 线路标识

配置新增两个独立字段：

- `sourcePlayFrom`：资源站原始播放标识，例如 `ikm3u8`。Worker 仅以此字段从 `vod_play_from` 中选择优先线路。
- `playFrom`：站内播放线路标识，例如 `ik`。Worker 将它写入所选线路的 `name` 和 `flag`，播放器、后台线路编辑和客户端解析规则均使用该值。

`sourcePlayFrom` 为空时，保留现有“优先 M3U8 线路”的回退选择。`playFrom` 为空时，所选线路继续使用资源站返回的原始标识。对于一个资源返回多条线路，只重命名与 `sourcePlayFrom` 匹配的线路；其他线路保留原始标识，避免将不相关线路错误归并。

旧配置只有 `source.playFrom` 时，继续将它视为原始匹配标识，保证既有任务不变；新表单会同时保存两项配置。

## 最大条目

`source.maxItems` 和兼容用的根级 `maxItems` 接受整数 `0` 到各自现有上限。

- 空值：沿用既有默认值（MacCMS 为 100）。
- 正整数：最多采集该数量的条目。
- `0`：不设置条目上限，但仍受 `maxPages`、类型筛选、年份/月筛选、重复跳过和停止信号约束。

Worker 使用显式 `None` 表示无限，不再用真值回退处理 `0`，从而不会回落为默认的 100 条。

## 封面开关

MacCMS 和 Hanime 表单均以 `media.enableCover` 保存“下载并保存封面”的状态。

- 勾选：URL 直入库模式保留可访问的上游封面 URL；S3/SFTP 模式下载并上传封面，上传失败时保留上游 URL。
- 取消勾选：不下载、不上传，且提交的 `coverUrl` 为 `null`，避免目录继续展示上游封面。

旧配置缺少该字段时按 `true` 处理，以维持原有默认行为。

## 表单与校验

MacCMS 表单明确展示“源播放标识”和“站内线路标识”，最大条目字段标注 `0 = 本次已配置页数全部条目`，并允许输入 `0`。封面复选框文案改为“下载并保存封面”，以区别于仅保存远程 URL。

服务器端 Zod 配置模式与表单转换同时接受上述字段，防止提交、存储、Worker 三层语义不一致。

## 验证

新增并执行下列定向测试：

1. 表单将两类线路标识、`maxItems=0` 和封面开关写入配置。
2. MacCMS Worker 用源标识选择线路，并将站内标识写入相应的 `name`/`flag`。
3. MacCMS 在 `maxItems=0` 时读取配置页数内的所有可用条目。
4. 关闭封面时，入库项与上传管道均不保留封面 URL。

不改动历史任务快照；新配置仅在新建或重新保存模板后生效。
