# 后台管理手册

后台地址为 `/admin`，登录页为 `/admin/login`。只有
`role=admin` 且 `is_active=1` 的用户可以访问。

## 1. 首次登录

先完成数据库 schema 审核和迁移，再初始化管理员。`npm run seed:admin` 会先发出
`CREATE TABLE IF NOT EXISTS users`，再检查并创建首个管理员；它不负责其他表、列或索引，
不能当作完整迁移命令。执行账号必须获准完成这条受控语句。

在可信的源码工作区中临时提供：

- `ADMIN_BOOTSTRAP_USER`：有效邮箱地址。
- `ADMIN_BOOTSTRAP_PASSWORD`：至少 12 位，不得包含
  `change-me`、`replace-with`、`admin123`、`password` 或
  `example` 等占位词。

然后运行：

```bash
npm run seed:admin
```

数据库已有管理员时，命令会跳过创建。项目不提供默认账号或密码。创建完成后：

1. 从环境中删除两个 `ADMIN_BOOTSTRAP_*` 变量。
2. 登录 `/admin`。
3. 在 `/admin/account` 确认身份并立即修改密码。

生产环境的完整顺序见
[生产发布检查教程](./tutorials/production-rollout.md)。

## 2. 功能导航

| 菜单 | 路径 | 能力 |
|------|------|------|
| 概览 | `/admin` | 里番、漫画、上架、标签、用户统计，以及最近内容状态 |
| 里番 | `/admin/animes` | 搜索、上下架、批量操作、删除和编辑 |
| 漫画 | `/admin/mangas` | 元数据、章节、页面、上下架和相关作品 |
| 里番标签 | `/admin/tags` | 里番标签创建、编辑、删除和分页浏览 |
| 漫画标签 | `/admin/manga-tags` | 漫画标签新增、重命名、删除、使用统计和分页浏览 |
| 用户 | `/admin/users` | 创建、改角色、启停、重置密码和分页浏览 |
| 系统 | `/admin/settings` | 注册、幻灯片、页脚链接、全局 Meta、搜索引擎收录、SMTP、Trust、播放器、广告、漫画发布和 Turnstile |
| 账户 | `/admin/account` | 当前管理员身份、发信状态和修改密码 |

后台顶栏提供日/夜主题切换。管理员也可以从前台 `/login` 登录，
再通过头像菜单进入「管理中心」。

## 3. 不可逆操作

删除内容前应先确认目标并保留数据库备份：

- 删除里番会删除作品及其标签关联，不能从后台恢复。
- 批量删除会逐条执行所选作品的删除操作。
- 删除漫画、章节或单页会删除对应记录；删除章节会同时删除其页面。
- 删除或改名漫画标签会更新所有使用该标签的漫画。
- 停用用户、重置密码或修改密码会使原有会话失效。

如果只需要暂时隐藏内容，优先使用「下架」，不要删除。

## 4. 里番管理

列表支持标题搜索、上下架、批量上下架、批量删除和单项删除。编辑页支持：

- 主标题、日文标题、英文标题
- 视频 URL、封面 URL、剧照 URL
- 简介和里番标签
- 上架状态

保存后会刷新相关页面缓存。播放器使用浏览器可访问的视频 URL，后台不会把
视频上传或搬运到本站。

## 5. 标签管理

里番标签字典对应 `tags`，作品关系对应 `anime_tags`。

- 名称必填且必须唯一。
- 修改后使用行内保存。
- 仍有关联作品的里番标签不能删除，应先解除关联。

漫画标签保存在每部漫画的 `mangas.tags`，与里番标签互不相通。
`/admin/manga-tags` 支持：

- 新增「常用标签」。未被作品使用时仍会保留，并显示在前台
  `/manga` 的快捷筛选中。
- 重命名标签。所有使用该标签的漫画会同步更新；与已有名称相同则合并。
- 删除标签。该名称会从所有漫画和常用标签中移除。

## 6. 漫画管理与发布

`/admin/mangas/:id` 可以编辑标题、作者、漫画标签、简介、封面和上架状态，
并查看章节、页面和同标签相关漫画。

- 章节可以单独上下架或删除。
- 页面缩略图按页浏览；链接视图一次列出当前筛选范围的全部地址。
- 页面 URL 可以逐条保存，也可以按现有顺序整批保存。整批保存时行数必须一致。
- 删除章节或页面后，章节和漫画页数会重新汇总。

漫画由 `POST /api/manga/publish` 写入，后台不提供 JSON 批量导入。启用前：

1. 在「系统 -> 漫画发布」启用漫画栏目。
2. 设置一个独立的高强度发布密钥。
3. 让外部发布端使用相同密钥，并通过以下任一请求头发送：
   `X-Manga-Publish-Key: <密钥>` 或
   `Authorization: Bearer <密钥>`。
4. 先发布一条测试章节，确认前台内容与图片正常，再投入自动发布。

请求至少需要 `title`、`sourceKey` 和非空 `imageUrls[]`。App 侧的密钥保存在
后台设置中，不写入 App `.env`；外部发布端仍需在自己的安全配置中保管同一密钥。
输入新密钥会立即替换旧值；轮换时应先安排发布端切换窗口，完成后验证旧密钥已经失效。

漫画榜单按阅读页产生的去重浏览事件累计。

## 7. 用户与账号

管理员可以创建用户、修改 `admin` / `user` 角色、启停账号和重置密码。
执行角色或启停修改前，应确认不会停用最后一个可用管理员。

前台账号能力包括邮箱注册、验证、密码找回、收藏和观看/阅读进度。邮箱验证与找回
密码依赖 SMTP。用户前台只看到统一结果；真正的发信状态应在
`/admin/account` 和 `/admin/settings` 检查。

## 8. 系统设置

### 注册与邮箱

- 注册开关
- 注册后是否必须验证邮箱
- 邮箱白名单
- 验证链接有效期

安全顺序：

1. 配置并启用 SMTP，保存。
2. 使用页面底部「发送 SMTP 测试邮件」验证真实收件。
3. 测试成功后再开启「注册后须邮箱验证」。

SMTP 密码留空表示保留当前值。若修改主机、账号或 TLS 模式，应重新发送测试邮件。

### Turnstile

Turnstile 有两层开关：

1. 「Cloudflare Turnstile」中启用，并填写 Site Key 和 Secret Key。
2. 「Trust（安全策略）」中分别选择注册或登录是否需要 Turnstile。

只有全局配置完整且对应 Trust 场景开启时，前台才要求挑战。Secret Key 留空表示
保留当前值。

### 首页与页脚

- 首页幻灯片最多 20 张，可混排里番作品和自定义幻灯片，并设置切换间隔。
- 幻灯片全部留空时，首页自动展示最近更新内容。
- Android 下载地址只接受 `http://` 或 `https://`。留空时页脚不显示入口。
- Telegram 地址与显示名称也在此配置；留空时不显示入口。

Android 下载地址应指向已验证的 GitHub Release 页面或其中的正式签名 APK。发布与
ABI 选择见 [移动端文档](./mobile.md)。

### 全局 Meta

在「系统 -> 全局 Meta」添加第三方要求的 `name` 或 `property` 与 `content`，
也可以展开「导入验证标签」粘贴完整的 `<meta ...>` 代码后导入。支持多条同名验证标签，
最多 50 条。修改后使用系统设置底部的保存按钮。

例如广告平台提供 `<meta name="google-adsense-account" content="ca-pub-...">`，
可直接导入；搜索引擎的 `google-site-verification`、`msvalidate.01` 等使用相同流程。
标签写入全站服务端 HTML 的 `<head>`，保存后会刷新页面及标签缓存。

验证标签只接受 `name` / `property` 与 `content`。网站自身的 viewport、字符集、
主题色与色彩模式仍由应用管理。脚本或广告 HTML 请配置在广告位中。

### 播放器与广告

- ArtPlayer 主题和右键菜单。
- 片头广告与暂停广告。
- 首页/目录信息流卡片和横幅。
- 漫画阅读页顶部和底部广告位。公开配置中的 `middle` 兼容字段当前固定禁用，后台不提供中部广告设置。

信息流和阅读广告可保存完整 HTML、iframe 或联盟脚本，包括 `document.write` 和异步外部脚本。
片头、暂停广告的 HTML 也在独立文档中运行脚本。广告位不会授予脚本访问网站父页面的权限。

#### 信息流广告：尺寸必须与素材一致

信息流广告有两种展示方式，网站（含手机浏览器）和 Android App 使用同一套配置：

| 展示方式 | 位置 | 尺寸怎么填 | 效果 |
|----------|------|------------|------|
| 信息流卡片 | 首页横向列表、`/browse`、`/manga` 网格中的一格 | 图片或固定像素素材：填写素材真实像素（如 `300×250`、`300×450`）；只有自适应 Native 代码才留「自动」 | 素材按比例完整放进 2:3 海报格并居中，不裁切 |
| 横幅 | 首页独立横幅条、目录里占两列的位置 | 填写素材真实像素（如 `300×250`、`728×90`） | 按素材比例占两列宽，等比放大或缩小 |

规则：

- **尺寸 = 素材的原始像素。** `<a><img></a>` 图片广告填写图片的实际宽高；联盟脚本填写联盟给出的
  单元尺寸。填错会导致留白或放大模糊。
- 卡片最合适的素材比例是 2:3（例如 `300×450`），能铺满整格；`300×250` 等横向素材会在格内居中并上下留白。
- 「自动」只适合会跟随容器宽高变化的 Native / 响应式代码。图片素材不要选「自动」，否则 App 里
  会按容器裁切。若尺寸留空但 HTML 中含 `atOptions`、`<iframe width height>` 或
  `<img width height>`，系统会自动读取其中的像素作为尺寸。
- 横幅在网页和 App 中都会等比放大到两列宽度；卡片最多放大到海报格大小。
- 每条信息流广告可单独开关和设置「每隔 N 张卡片」，最多 12 条。

在「广告尺寸」中选择 `320 × 50`、`320 × 100`、`300 × 250`、`336 × 280`、
`468 × 60`、`728 × 90`、`970 × 90`、`970 × 250` 或 `300 × 600`，也可填写自定义尺寸。
自定义宽度最多 `1920`、高度最多 `600`；「自动」跟随内容高度，最高 `600`。
阅读页顶部/底部广告同样按素材原始像素配置，超过屏宽时等比缩小。旧配置保持自动尺寸。

播放器视频和广告素材 URL 必须能被用户浏览器直接访问。本站没有通用视频或任意图片
代理；只有固定上游 `image.ixacg.de` 的图片可以通过受限的 `/cdn-img/**`
图片代理读取。不要把该路径当作通用 CDN 或视频代理。

### 搜索引擎收录

网站已内置以下收录能力，管理员只需要完成验证、提交站点地图和可选的 IndexNow 密钥：

| 项目 | 地址 / 位置 | 说明 |
|------|-------------|------|
| 站点地图索引 | `{SITE_URL}/sitemap.xml` | 索引文件，指向 `/sitemaps/pages.xml`、`animes-N.xml`、`mangas-N.xml`、`tags-N.xml`、`manga-tags-N.xml`；每个文件最多 10,000 条，详情页附带封面图片 |
| robots | `{SITE_URL}/robots.txt` | 屏蔽后台、API、广告文档、搜索结果和账号页；声明站点地图 |
| 验证标签 | 系统设置 → 全局 Meta | 导入 `google-site-verification`、`msvalidate.01`（Bing）等 |
| IndexNow | 系统设置 → 搜索引擎收录 | 填写密钥后，发布漫画、编辑或上下架里番/漫画时自动通知 Bing（Edge）、Yandex 等 |

操作顺序：

1. 在 [Google Search Console](https://search.google.com/search-console) 和
   [Bing Webmaster Tools](https://www.bing.com/webmasters) 添加站点，把验证 `<meta>` 导入「全局 Meta」并保存。
2. 在两个后台分别提交 `https://<站点>/sitemap.xml`。索引文件会自动列出所有分片，不需要逐个提交。
3. 生成一个 IndexNow 密钥（8 到 128 位字母、数字或连字符，例如 `openssl rand -hex 16`），填入
   「搜索引擎收录」并保存。网站会自动在 `/indexnow/<密钥>.txt` 提供密钥文件，不需要上传任何文件。
   之后每次内容变化都会自动提交对应 URL；Bing Webmaster 的「IndexNow」页可以看到提交记录。
   Google 不支持 IndexNow，依赖站点地图与站内链接。
4. 在「漫画标签」中把希望被收录的标签设为「精选」。只有精选漫画标签页
   （`/manga?tag=...`）会被索引并进入站点地图；其余自由标签页保持 `noindex`，避免几千个重复的薄页面。
   里番标签页 `/browse?tag=ID` 全部可索引，并会自动解析标签名作为标题。

哪些页面可被索引：首页、`/browse`（含标签与分页）、`/manga`（含榜单、分页与精选标签）、
`/watch/{id}`、`/manga/{id}`、隐私与条款。搜索结果、阅读器页面、账号、历史、收藏、后台和 API
均为 `noindex` 或被 robots 屏蔽。

站点内容属于成人向，全站带有 `<meta name="rating" content="adult">`。这是 Google 与 Bing 对成人站点的
标注要求，用于 SafeSearch 分类，不会阻止收录；如需去掉，可在 `lib/seo.ts` 调整。

### 密钥保管

SMTP 密码、Turnstile Secret 和漫画发布密钥使用
`APP_ENCRYPTION_KEYRING` 加密后存入数据库。备份数据库时必须同时安全保管仍用于
解密的 keyring；丢失或过早删除旧 key 会使已保存的密文无法读取。所有密钥输入框
留空都表示保留现值，不表示清空。

## 9. 日常检查

完成后台修改后至少检查：

- 前台对应内容是否出现或消失。
- 登录、注册、邮件或 Turnstile 是否仍按预期工作。
- Android / Telegram 页脚链接是否打开正确目标。
- 漫画发布测试是否返回成功，章节图片是否可读。
- 删除或批量操作后的数量、分页和上下架状态是否正确。
