# Android 安装与更新

本教程帮助你从项目的正式 GitHub Release 选择正确 APK、完成首次安装，并理解 App 后续如何
提醒更新。完整行为和开发者发布信息见 [原生 Android 客户端参考](../mobile.md)。

完成后，你应能打开 `AnimeStream` 首页、在“我的”页看到 Build，并知道本机数据与网站账号的
同步边界。

## 开始前

- 设备需运行 Android 7.0 或更高版本。
- 公开安装包只从
  [SakurajimMai/hentaiworkers Releases](https://github.com/SakurajimMai/hentaiworkers/releases)
  下载，不使用来源不明的 APK，也不使用 GitHub Actions 内部 Artifact。
- 工作流会把公开版本标为 prerelease；请以正式 Releases 页面和完整五种 APK 为准，不要因此
  改去下载内部 Artifact。
- 首次安装需要允许侧载。Android 7.0/7.1 通常使用系统安全设置中的全局“未知来源”开关；
  Android 8.0 及以上通常对当前浏览器或文件管理器授予“安装未知应用”权限。厂商入口名称
  可能不同，安装完成后可撤销刚才启用的开关或来源权限。

> **如果设备装的是 Build 39 或更早版本，请先停下。**
>
> 这些版本使用旧 Expo debug 证书，不能覆盖安装新的生产签名版本。先在旧版登录并确认数据
> 已同步，或自行备份，再卸载旧版。卸载会删除未同步的本机收藏、历史和 Cookie，首次启动
> 迁移无法恢复已被卸载操作删除的数据。

## 1. 选择 APK

打开最新的 `build-<数字>` Release，展开 **Assets**，按设备 CPU 选择：

| APK | 选择场景 |
|-----|----------|
| `arm64-v8a` | 大多数现代 Android 手机，推荐 |
| `armeabi-v7a` | 较旧的 32 位 ARM 手机 |
| `x86_64` | 64 位 Intel 模拟器或少量 Intel 设备 |
| `x86` | 32 位 Intel 模拟器或少量 Intel 设备 |
| `universal` | 不知道设备架构时使用，体积更大 |

普通手机先选 `AnimeStream-<build>-arm64-v8a.apk`。只有安装器提示架构不兼容，或你无法确认
CPU 架构时，才改用 universal。

Release 的 `SHA256SUMS` 列出五个 APK 的 SHA-256。高级用户可在安装前自行计算下载文件的
哈希并与同名记录比较；App 不会读取浏览器下载后的文件替你完成这一步。

## 2. 完成首次安装

1. 点选 APK，等待浏览器下载完成。
2. 打开下载文件。若系统拦截，Android 7.0/7.1 在安全设置中临时启用“未知来源”；Android
   8.0 及以上只允许当前浏览器或文件管理器“安装未知应用”，然后返回继续。
3. 在 Android 安装器中确认安装。
4. 打开 `AnimeStream`，等待首页结束加载并显示目录内容或明确的空/错状态。
5. 进入“我的”，确认页面能显示版本名与 `Build <数字>`。
6. 安装完成后，如不再需要侧载其他应用，可关闭 Android 7.0/7.1 的全局开关，或撤销 Android
   8.0 及以上对该来源的安装权限。

如果系统提示“应用未安装”、签名冲突或无法覆盖，不要反复下载同一文件：

- Build 39 及以前按上方警告先同步/备份，再卸载旧版。
- 已安装较新的正式版时，确认新 APK 也来自项目正式 Release；来源不明或签名不同的 APK
  不应通过卸载正式版来强行安装。
- 确认设备为 Android 7.0+、存储空间充足，并尝试该 Release 的 universal APK。

## 3. 登录与确认数据边界

目录、播放和阅读无需登录。需要同步收藏和历史时：

1. 按 [前台使用指南](../user-guide.md) 在网站完成注册、邮箱验证或密码重置；App 本身没有这些入口。
2. 在 App 打开“我的 -> 登录”。
3. 输入网站账号的用户名或邮箱和密码。
4. 返回“书架”，确认副标题显示已与账号同步。

未登录时，收藏和历史只存在本机；里番历史与漫画历史各保留最近 50 条。登录后，App 会尽力
把本机记录合并到账号并优先读取云端，但 Android 书架也只请求云端里番历史与漫画历史最近
各 50 条；更早记录仍可在 Web `/history` 分页查看。网络失败时可能回退到本机已有数据，但这
不是完整的离线云端副本。卸载 App 会删除未同步的 Room 和 DataStore 数据。

两类进度不要混淆：

- **里番：** Android 当前只保存“观看过”的标记，不保存 Media3 的真实播放秒数。书架历史
  会返回作品详情，不能像 Web 一样按秒续播或跨设备恢复视频位置。
- **漫画：** Android 保存章节和页码，书架可从该位置继续阅读；登录后会尽力同步到账号。
  当前 Web 阅读器不会自动使用云端 `pageIndex` 跳到 Android 的精确页码。

## 4. 快速检查播放与阅读

安装后的最小烟测：

1. 在“发现”打开一部里番并进入播放；确认播放器转为横屏，播放/暂停、拖动、倍速和画面
   比例可操作，返回后恢复竖屏。
2. 在“漫画”打开一章；上下滚动，轻点页面显隐工具栏，拖动底部进度条并确认页码实时变化。
3. 返回“书架 -> 历史”；里番记录应打开作品详情，漫画记录应回到保存的章节和页码。

播放器支持 MP4/HLS，但作品可能使用外部媒体地址。目录能打开并不保证每个图片 CDN 或视频源
在当前网络都可达。

## 5. 接收并安装后续更新

App 在首页目录加载完成后发起一次独立更新检查。该检查不会阻塞或清除首页内容：

- 确认当前版本已是最新后，24 小时内不重复自动检查；失败后六小时再尝试。
- “我的 -> 检查更新”可随时手动检查。
- 有新 Build 时，弹窗会选择适合设备的 ABI；无法识别时使用 universal。
- 点“立即更新”会打开外部浏览器下载 APK，然后仍由 Android 安装器要求你确认。
- 新版在弹窗展示前不会直接记成已提醒；点“立即更新”成功打开链接或点“稍后提醒”后，会对
  这个 Build 暂停提醒 24 小时。

更新机制不是通知栏推送、后台下载、静默安装或强制升级。App 未运行、首页尚未完成加载，或
更新检查暂时失败时，不会收到即时推送。首次安装带此机制的版本后，它才能提醒后续版本。

下载新 APK 后直接打开并确认覆盖安装。只要包名和生产签名一致，收藏、历史和登录状态会保留；
不要在正常覆盖更新前卸载 App。

## 6. 排查常见问题

### 首页长时间转圈或提示“服务器响应超时”

手机能访问其他服务不代表站点 API、DNS 或代理链路正常：

1. 点页面的重试按钮，不要持续等待旋转状态。
2. 用同一手机浏览器打开站点，比较网页是否也超时。
3. 分别测试 Wi-Fi 和移动数据。
4. 比较启用与停用代理、VPN 或私有 DNS 后的结果。
5. 若持续失败，记录“我的”页的 Build、失败页面和完整错误文案后联系管理员。

“网络连接失败”通常指 DNS、TLS 或连接不可达；“服务器暂时不可用”表示服务端返回 5xx；
“响应不是合法 JSON”常见于 Wi-Fi 登录门户、异常代理或服务端错误页。

### 首页能开，但图片或视频失败

- 只有图片失败：重试本页并切换网络，问题可能在图片/CDN 层。
- 只有某部视频失败：先重试，再测试其他作品；只有单部失败时报告作品名和错误。
- 筛选后没有内容：这是成功空结果，点“清除筛选”，不要一直刷新。

### 更新检查失败

更新同时依赖站点更新清单和 GitHub Releases。稍后在“我的”手动检查，或直接打开公开 Releases
页面。自动检查失败不会影响目录、播放或阅读。

### 冷启动暂时显示未登录

弱网可能让 `/api/me` 会话验证失败。本次运行会暂时显示未登录，但持久 Cookie 不一定已被
删除。恢复网络后重启 App 或重新进入“我的”确认；不要因此立即卸载 App。

提交故障信息时，请提供 App 版本与 Build、Android 版本、网络类型、页面或作品、完整错误文案
及网页端对照结果。不要发送密码或 Cookie。

## 结果检查

完成教程后，应满足：

- APK 来自项目正式 GitHub Release，且与设备 ABI 匹配。
- App 能打开首页并结束初始加载，“我的”页能显示 Build。
- 你知道登录前数据只在本机，卸载会删除未同步数据。
- 你知道里番只保存观看标记，漫画才保存精确章节与页码。
- 你知道更新需要 App 拉取检查、浏览器下载和系统确认，不是推送或静默安装。

更多实现、CI、签名与发布验收信息见 [原生 Android 客户端参考](../mobile.md)。
